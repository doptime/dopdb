# 开题报告 · Round1-20260819-fixes-peformance-improve

## 一、这一轮要解决什么

上一轮把 dopdb 的底层存储从 MongoDB 换成 KVRocks（值格式 BSON → CBOR），并补了 SQL
查询层。随后的两次审计（`ProblemDetected.md`、`ProblemDetectedScan2.md`）指出迁移
留下了一批问题。本轮处置 `ProblemDetectedScan2.md` 的 50 条，并**在实测基础上**做
一轮查询引擎性能优化。

一句话概括本轮的性质：**这不是一次功能开发，是一次止血 + 补测量。**

## 二、核实结论（不是照单全收）

审计报告的 50 条，我逐条对着源码验证。结论分三类：

| 类别 | 数量 | 说明 |
|---|---|---|
| 属实并已修复 | 32 | 见各 package |
| 属实但判断**不改** | 2 | 有明确理由，见 package-06 / package-07 |
| 已在当前代码中不存在 / 描述需修正 | 若干 | 例如 publish workflow 的 KVRocks 改动其实已提交 |

**报告最有价值的不是任何单条，而是它的元观察**：上一轮的四个修复只落在 Go 端，
TS 端全部未同步（S2-5/6/29/30）；而 conformance 对 watch、hgetall 族、错误码差分零
覆盖，且 TS 侧用 `permit: () => true` 绕过了权限门。**这正是双端分叉能存活的原因。**
所以本轮除了修 bug，还必须修"为什么没人发现"——见 package-09。

### 补测试过程中新发现的两条（审计报告里没有）

1. **watch 事件字段双端不一致**：Go 发 `id`，TS 客户端类型声明的是 `key`。
   TS 客户端连 Go 服务端时 `ev.key` 恒为 `undefined`。
2. **未知集合的响应分裂**：Go 先查权限返回 403，TS 先查注册返回 404。

两条都是在写 conformance 用例的当场被抓出来的，这本身说明 package-09 的必要性。

### 修复过程中我自己写错的一次

有界 top-N 堆的第一版，sift 比较方向反了，保留的是**最差**的 N 条而不是最好的 N 条。
是 conformance 和集成测试把它抓出来的（`LIMIT 2 => [n:3, n:4]`，应为 `[n:0, n:1]`）。
修复后补了随机化等价测试。这条写在这里，是因为它是本轮"测试先于信心"这个主张的
最好证据。

## 四、方法

每一条都走同一条流水线，缺一不可：

1. **源码核验** —— 不接受"报告说了"，只接受在源码里指出确切位置。
2. **复现** —— 尽可能写出能在修复前失败的证据（基准、探针、竞态循环）。
3. **修复** —— 双端同改，或明确说明为何只改一端。
4. **回归测试** —— 每个真问题都留一个测试守着。**之前 11 个真问题一个测试都没有，
   这正是它们能活下来的原因。**
5. **文档** —— 行为变了就改文档；覆盖没到就把话说小。

### 无服务器时必须"干净跳过"

这是硬要求：需要服务器的用例必须 skip 而不是失败，否则 CI 会因为环境问题变红，
最终没人看。反过来，**CI 里 conformance 被 skip 必须让构建失败**——绿灯跑在空气上
正是本轮要防的事（见 package-09）。

## 七、本轮做不到的事

诚实列出，不要让它们在验收时变成意外：

1. **npm 发版**：需要凭据与发布权限。线上 `@kequnyang/dopdb` 仍是 Mongo 版，
   值格式（BSON vs CBOR）与 Perm 位图（新增 SQL 位）都不兼容——**老客户端连新服务端
   会坏**。发版必须标成 breaking change。package-09 修了 dist-tag 逻辑，但发版动作本身
   要人来做。
2. **真机 KVRocks 验证**：本轮在 Redis 7.0（协议兼容）上验证。KVRocks 的
   `SET`-on-hash 静默类型转换是其特有行为，package-04 的保留名用例建议在真机上再跑
   一遍。
3. **TS 集合类型系统**：Go 里 `NewList`/`NewSet` 是不同类型，TS 里所有集合都是
   `collection()`。这条结构性差异本轮**记录并测试**，没有消除——消除它是 API 新增，
   不是修 bug。详见 package-06。
4. **watch 续传**：本轮**故意不做**。理由见 package-07。
